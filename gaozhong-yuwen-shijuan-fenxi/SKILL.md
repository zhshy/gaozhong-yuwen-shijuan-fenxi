# 高中语文试卷与答卷分析

按"四问主线 × 五层字段"编码一份高中语文试卷，得出它的考查范围；再与学生的答卷逐题比对，得出该生的优势与劣势。适用于统编版必修与选择性必修。

## 何时使用

用户上传高中语文试卷、月考卷、模拟卷、真题，或上传学生的答题卡、答卷，并提出以下任一意图时使用：

- 想知道这张卷子考了什么、覆盖范围到哪
- 想知道这个学生哪里强、哪里弱
- 想把试卷和答卷一起分析

用户只说"分析一下这份卷子""看看这学生问题在哪"时也要触发。

## 不做什么

- 不替学生作答，不给应试话术模板或所谓"答题公式"
- 不臆造课程标准条目编号、分值或评分细则
- 不在字迹无法辨认时猜测作答内容
- 不修改、移动或删除用户上传的任何原文件
- 不联网检索真题原文，一律以用户上传的材料为准
- 缺少评分依据时不声称"精准判分"

## 第一步：问清本次任务

用户未说明时，先问一句本次要做什么。三种任务，不默认全跑：

| 任务 | 用户典型说法 | 执行范围 |
|---|---|---|
| 只看考查范围 | "这卷子考了什么" | 步骤二、三、六 |
| 只看学生答卷 | "看看这学生哪里弱" | 步骤二、四、五、六 |
| 两者都做 | "卷子和答卷一起分析" | 全部步骤 |

用户已明确说明时直接进入对应步骤，不重复追问。

## 第二步：检查输入

运行只读检查，确认文件存在、格式可读、有没有评分细则。

```bash
python scripts/check_inputs.py <试卷路径> [答卷路径...]
```

检查输出三种状态：

- `ready`：试卷与评分依据齐全，进入正常流程
- `partial`：缺评分细则或缺答卷，进入受限流程并标注
- `missing`：试卷文件不存在或无有效文本，停止并请用户补充

检查只读文件，不修改任何内容，不联网。

按检查结果确定证据等级：

| 等级 | 条件 | 允许的结论强度 |
|---|---|---|
| A 已核验 | 有评分细则且答卷可清晰识别 | 可给精确分，可做单点失分分析 |
| B 部分验证 | 有参考答案无细则，或部分字迹模糊 | 给区间分，模糊处标出待确认 |
| C 推断 | 仅有总分或等级，无逐题痕迹 | 只做板块层面粗判，不落到采分点 |
| D 未验证 | 关键内容无法辨认且用户无法确认 | 不出结论，只列待确认项 |

报告中每个结论后必须标注其证据等级。等级 D 的内容不出现在结论里。

## 第三步：编码试卷

按 `@references/fields-l1-l5.md` 的定义，逐设问登记 L1 至 L5 五层字段。分析单元是**设问**，一道大题含多个小问时逐小问登记；选择题的选项另建子表。

编码时遵守四条硬规则：

1. 知识与能力双编码。"考查比喻"记入 L3 考点，"考查鉴赏能力"另记 L3 认知层级，两者不合并。
2. 情境类型只用课程标准的三类：个人体验情境、社会生活情境、学科认知情境。不另造分类。
3. 主观题必须同时编码题干、参考答案与评分细则三者。只有题干时，评分标准字段记 `未提供`。
4. 分值只登记试卷上的实际数值，不预设分值档与要点数量的换算关系。

编码完成后统计并输出：

- 板块分值结构与主客观题配比
- 考点频次矩阵（年份或板块 × 考点）
- 双向细目表（内容板块 × 能力层级，格内填分值）
- 覆盖空缺：该卷未涉及的常考考点

## 第四步：比对答卷

逐设问比对学生的作答与参考答案、评分细则。

采点给分与分层给分的判读方式不同，先判定评分方式再判分，规程见 `@references/scoring-analysis.md`。

记录每位学生的以下字段：

- 逐设问得分与满分
- 逐采分点得失（仅当有评分细则时）
- 失分类型：知识空缺、理解偏差、表述不成型、时间不足、粗心
- 同分不同病判定：同分学生失分机理是否一致

字迹模糊、涂改严重、答案跨区书写的部分，标记为待确认并列出，不推测内容。

## 第五步：判定优劣势

按板块与考点聚合得分，判定优势与劣势。结论必须挂数据，每条结论后标注证据等级。

判定时遵守：

1. 得分率高于卷面整体得分率 10 个百分点以上，且样本不少于 3 个设问，才判为优势。
2. 低于整体得分率 10 个百分点以上，且样本不少于 3 个设问，才判为劣势。
3. 样本不足 3 个设问的考点只作提示，不下强弱结论。
4. 同分不同病的学生必须分开表述，不合并成一句"该生此处较弱"。

## 第六步：出报告与数据表

按 `@references/report-template.md` 生成报告，报告中每个结论标注证据等级。

生成数据表：

```bash
python scripts/make_workbook.py --input <编码结果.json> --output <数据表.xlsx>
```

数据表包含三张工作表：逐题编码表、学生得分对照表、双向细目表。

若数据表生成失败，保留结构化内容并以 Markdown 表格输出，明确告知文件未生成。

报告中的补强建议只写方向与靶点，不写具体话术，不替学生作答。

## 停止条件

出现以下任一情况时停止当前流程并说明：

- 试卷文件不存在、无法解析或没有有效文本内容
- 试卷缺少题干，无法确定考查点
- 试卷与答卷不匹配（科目、题号或卷别不一致）
- 学生答卷关键内容无法辨认，且用户无法补充说明
- 用户要求判定某学生得分但无任何评分依据
- 用户要求修改、删除或移动原始文件

停止后保留已完成部分，标注未完成范围，不用推测结果填充。

## 输出前自查

- 每个结论后是否标注了证据等级
- 是否存在只有结论没有数据支撑的判断
- 考点与能力是否分列两栏，未合并
- 情境类型是否只用了课程标准的三类
- 主观题是否同时编码了题干、参考答案与评分细则
- 分值是否只登记实际数值，未做换算
- 字迹模糊处是否标记为待确认而非推测
- 优劣势判定是否满足样本量要求
- 报告是否包含补强建议
- 是否改动过用户上传的任何原文件
